# Assignment briefs

Link needed context rather than duplicating whole instructions or logs. Main selects a registered role and passes only the work it owns.

## Implementation or planning

```text
Purpose: <plan/implement/docs>. Workdir: <absolute path>.
Goal and done when: <request and acceptance criteria>.
Own only: <files>; non-goals: <limits>.
Context and dependencies: <contracts, applicable plan, ready prerequisites>.
Verify with: <commands and expected outcomes>.
You are not alone; preserve others' edits and report conflicts to main.
Do this work directly. Do not spawn agents, message peers/users, run basic-team
or write Office/HTML/Notion. Report only to this session.
Use applicable installed Karpathy/Ponytail guidance and preserve the active level.
For plan-only work, return a plan without implementing.
Return status, changed files, actual checks/results, unresolved/unchecked items
and any necessary evidence path. Notify main of start/done/failure/wait transitions.
```

## Independent review

```text
Read-only review of <owned patch/files> against <base>, revision <hash>.
Goal and acceptance criteria: <criteria>. Existing evidence: <checks>.
Changed delta and accepted decisions: <delta/decisions>.
Check correctness and relevant callers/edge cases. Do not edit source or
start other agents/reporting runs. Return only to main.
Required findings need an evidenced in-scope defect, regression, security/data-loss
risk or unmet explicit criterion. Taste/adjacent cleanup/speculation are advisory.
Missing required evidence is BLOCKED; tool failure alone is not a product defect.
Return verdict PASS/CHANGES_REQUIRED/BLOCKED, findings with required/advisory,
file:line, trigger and evidence, plus checked/unchecked areas and actual commands.
```

For affected UI or connected-flow checks, main supplies screens/states, relevant viewports/languages/themes, startup, fixtures and test accounts. Use installed Impeccable/browser guidance where applicable. Verify observable outcomes, not just page loading. An unavailable interaction stays unchecked. Clean up only this run's test data/tabs; do not touch production data, payments or external messages. Read-only review forbids product edits; test commands may create normal local test artifacts.
