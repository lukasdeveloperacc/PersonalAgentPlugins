# Obsidian 업무 기록

이 스킬은 업무 절차를 담당한다. 노트는 사용자의 별도 Obsidian vault에 저장한다.

## 대상과 도구

- 사용자 지정 경로, 프로젝트 문서의 vault 지정, 확인된 Obsidian 설정에서 **이번 작업의 대상 vault**를 식별하고 실제 경로를 확인한다. 현재 저장소나 앱에서 열린 vault를 임의로 대상으로 삼지 않는다. 대상을 확정할 수 없으면 경로를 물으며, 확정 전에는 쓰지 않는다.
- 대상 vault와 수정할 폴더에 적용되는 `AGENTS.md`, `CLAUDE.md`를 읽고 기존 폴더 구조·노트 형식·날짜 기준을 따른다. 지정된 기록 위치가 없으면 기존 일일 노트와 프로젝트 노트에서 적절한 위치를 찾는다. 후보가 모호하면 저장 위치를 묻는다.
- 일반 Markdown 조회·수정은 로컬 파일 도구를 사용한다. Obsidian 고유 문법은 설치된 `obsidian-markdown`, Bases와 Canvas는 해당 upstream 스킬을 참고한다.
- 앱 검색, 백링크, 미해결 링크, 고아 페이지, 링크를 보존하는 이동·이름 변경은 `obsidian-cli` 스킬과 실제 `obsidian help`로 지원 명령을 확인한다. 모든 CLI 작업에서 대상 vault를 명시하고 명령에 맞는 인자를 사용한다. CLI는 실행 중인 Obsidian 앱이 필요하다. 사용할 수 없으면 가능한 파일 작업을 진행하고 검증하지 못한 앱 기능을 구분해 보고한다.
- 이 스킬은 도구 설치, MCP 등록, 자동 기록 훅 설정, Git 커밋·푸시를 실행하지 않는다. 그런 작업은 별도 요청 범위다.

## 업무 시작

요청한 프로젝트와 관련된 최근 업무 기록, 결정사항, 미완료 작업을 읽는다. 목차가 있으면 탐색에 활용하고 전체 vault를 한꺼번에 읽지 않는다. 현재 상황·이어 할 일·열린 질문을 근거 노트 링크와 함께 짧게 정리한다. 시작 요청만으로 노트를 수정하지 않는다.

## 업무 종료와 기록

이번 세션에서 확인한 작업 결과, 결정과 근거, 후속 작업, 미해결 질문을 기존 기록 위치에 추가한다. 완료하지 않은 작업을 완료로 기록하거나 담당자·기한을 만들어내지 않는다.

쓰기 직전에 대상 노트를 다시 읽고 기존 내용과 사람이 쓴 메모를 보존한다. 같은 세션 내용을 이미 기록했다면 중복 추가 대신 해당 기록에 새 사실만 반영한다. 관련 프로젝트·결정 노트가 있으면 연결하고, 저장한 경로와 핵심 변경을 보고한다.

## ingest — 자료 반영

원본 자료와 기존 관련 노트를 읽고 새 사실이 어떤 기존 설명·결정·절차를 바꾸는지 판단한다. 단순 요약 파일을 늘리기보다 관련 노트에 내용을 통합하고 필요한 연결을 보완한다. 수정할 페이지 수를 정해 채우지 않는다.

원본은 보존하고 출처 파일·URL·날짜를 추적할 수 있게 남긴다. 기존 `raw/`, `wiki/`, 목차, 변경 기록이 있으면 그 규칙을 따른다. 원본과 노트가 충돌하면 각 근거와 시점을 표시하며, 근거 없이 한쪽을 지우거나 사실로 확정하지 않는다. 새 자료가 기존 내용을 바꾸지 않으면 중복 노트를 만들지 않는다.

## query — 근거로 답변

질문에 관련된 노트를 찾아 답변에 근거 노트와 필요한 원본 출처를 연결한다. 기록된 사실, 추론, 미확인 내용을 구분한다. vault에 근거가 없으면 없다고 밝힌다. 질문에 답하는 동안 노트를 수정하지 않는다.

## lint — 연결과 내용 점검

요청 범위의 깨진 링크, 고아 페이지, 중복 설명, 서로 충돌하는 주장을 점검한다. 동명 노트·별칭·헤딩·블록 링크를 고려하고, 단순 파일명 비교만으로 깨진 링크를 확정하지 않는다.

구조상 오류와 내용상 판단이 필요한 모순을 구분한다. 수정 요청이 있으면 목적지가 확인되는 링크 등 근거가 명확한 부분을 고친다. 고아라는 이유로 페이지를 삭제하거나 관계없는 링크를 추가하지 않는다. 모순은 출처와 시점을 대조하고 해결 근거가 부족하면 열린 문제로 남긴다. 점검 범위, 수정 경로, 남은 문제와 검증 한계를 보고한다.
