# TheGame 업무 추적

사용자가 이 스킬로 추적을 요청하거나, 작업 시작 질문에 TheGame 업무라고 답하거나, 이미 확인된 TheGame 작업의 시작·PR 연결·마감을 요청할 때 적용한다. 개인 작업과 다른 회사 업무는 Notion 추적 없이 진행한다. 이전 세션의 링크나 같은 저장소에서 작업한다는 사실만으로 새 요청을 TheGame 업무로 분류하지 않는다.

TaskBoard의 Task 한 장을 업무 기준으로 삼는다. 메인 세션이 Notion을 기록한다. 훅이 알려준 URL은 재개 단서다. 현재 요청과 같은 업무인지 확인한 뒤 사용한다.

## 시작과 재개

1. [TaskBoard](https://app.notion.com/p/33b8a6cfb7d48026833cc7effb3b6111?v=33b8a6cfb7d481328940000c2f0e3a80&source=copy_link)를 Notion MCP로 읽고 연결된 사용자를 확인한다. Git 워크트리에서는 작업 디렉터리에서 이 스킬의 [task_state.py](scripts/task_state.py)를 절대 경로로 실행한다. `python3 <스크립트> show`로 기억된 Task URL을 확인한다.
2. 사용자가 지정한 Task, 기존 basic-team 보고의 Task URL, 워크트리에 기억된 URL 또는 Scrum TODO의 실제 링크로 기존 Task를 확인한다. 제목만 같은 항목을 임의로 선택하지 않는다. 같은 업무면 재사용하고, 착수하는 TODO는 `IN PROGRESS`로 바꾼다. 사용자가 완료된 업무를 다시 열었으면 Task를 `IN PROGRESS`로 바꾸고 해당 Scrum TODO도 미완료로 되돌린다. 완료 동기화 도중 끊겼다면 아래 완료 절차의 빠진 변경만 복구한다.
3. 신규 업무라면 TaskBoard의 데이터 소스(기존 ID `33b8a6cf-b7d4-8106-bca5-000bef4c35a9`)에 하나 만든다. 실제 스키마에 맞춰 `업무명`, `Status = IN PROGRESS`, `작성자`와 `담당자`는 연결된 사용자, `작업유형`은 요청 유형, `프로젝트`는 저장소와 일치하는 기존 옵션을 사용한다. 본문에 목표와 완료 기준을 짧게 적는다. Task를 확인하거나 생성한 직후 `python3 <스크립트> remember <Task-URL>`로 기억한다. 다른 Task를 이미 기억 중이면 덮어쓰지 않고 두 URL을 구분해 전달한다. Git 밖이거나 로컬 기록이 실패하면 Task URL을 사용자에게 전달하고 Scrum 또는 팀 보고의 링크로 재개한다.
4. Task를 만들거나 기존 업무를 이어서 수행할 때는 **이번 요청 시점의 업무일**을 확인한다. 사용자 현지 시간대(기본 한국 시간, `TZ=Asia/Seoul date +%F`)를 사용한다. 같은 대화에서도 날짜는 바뀔 수 있다. 이번 Task를 그 날짜의 내 Daily에서 확인한 기록이 없으면 본작업 전에 아래 절차를 수행한다. Task URL과 기존 추적 동의는 그대로 사용한다. 상태 조회나 이전 업무일의 마감·복구만 요청한 경우에는 해당 날짜의 기존 기록을 처리한다.

### 오늘 Daily에 즉시 반영

1. [Daily Scrum](https://app.notion.com/p/Daily-Scrum-38b8a6cfb7d480cdb99fc194eba2e5bb?source=copy_link)의 **Daily Scrum DB**(`collection://f9dfaeca-30cf-4f95-93da-4425d3170360`)에서 이번 업무일의 `Date`와 연결된 사용자의 `작성자`가 모두 일치하는 페이지를 찾는다. 대화에 나온 링크나 Task의 역링크도 두 속성을 확인한 뒤 사용한다. 어제 링크는 이력으로 남긴다. 필터 조회가 어려우면 DB 안에서 `MMDD 이름`으로 찾아 속성을 확인한다.
   - 오늘 내 페이지가 있으면 그 페이지의 본문을 연다. 다른 작성자의 같은 날짜 페이지는 건드리지 않는다.
   - 조회 결과 오늘 내 페이지가 없으면 같은 DB에 일별 템플릿으로 **오늘 Daily를 새로 만든다**. 제목은 기존 `MMDD 이름` 형식, `Date`는 이번 업무일, 상태는 `Doing`을 사용한다. 읽기 전용인 `작성자`는 생성 후 확인한다. 템플릿을 적용할 수 없으면 기존 일일 페이지의 섹션 제목만 재현하고 어제의 체크박스는 복사하지 않는다. 생성한 페이지의 날짜·작성자·본문을 확인하고 아래 단계로 이어간다. 조회 실패는 빈 결과로 취급하지 않으며 생성 응답이 불확실하면 같은 날짜·작성자로 재조회한 뒤 재사용한다.
2. 본문의 **🎯 오늘 할 일** 제목부터 다음 같은 수준의 제목 직전까지만 살핀다. 같은 Task 페이지 ID를 가진 체크박스가 있으면 재사용한다. 동일한 업무의 텍스트 체크박스만 있으면 그 자리에 Task 페이지 멘션을 넣는다. 없으면 다른 항목을 보존하며 그 구역 안에 체크박스 한 줄을 추가한다. 현재 템플릿에서는 `## 🚧 막힌 것` 바로 앞에 `- [ ] <mention url="Task 페이지 URL">업무명</mention>` 형식으로 넣는다. 기존 `<todo>` 블록의 멘션도 같은 항목으로 취급하며 URL의 쿼리와 하이픈 차이는 무시하고 페이지 ID를 비교한다. 다른 구역의 링크, 페이지 속성, 본문 맨 끝에 붙인 링크는 오늘 할 일로 세지 않는다.
3. 쓰기 직후 해당 Daily를 다시 fetch해 오늘 할 일의 체크박스에서 **같은 Task 페이지 ID**와 체크 상태를 확인한다. 진행 중이면 미체크, 이미 완료된 업무를 복구하는 경우에는 체크 상태로 맞춘다. 요청이 실패하거나 결과가 불확실하면 최신 본문을 먼저 읽고, 빠진 경우에만 해당 구역을 한 번 보완한 뒤 다시 확인한다. Task에는 기존 날짜의 링크를 보존하며 확인한 오늘 항목의 링크(가능하면 블록 링크)를 한 번만 남긴다.
4. 본작업에 들어가기 전 사용자에게 **Task와 오늘 Daily 두 링크**를 함께 보여준다. 확인이 끝나지 않았으면 Task URL, Daily 기록이 보류된 구체적 이유와 해당 업무일을 먼저 알린다. Task에 쓸 수 있으면 그 날짜와 확인된 Daily 링크를 동기화 보류 항목으로 남기고, 복구 후 해당 보류 표시만 해제한다. 독립적인 본작업은 진행할 수 있으며 다음 동기화 때 기존 Task로 빠진 Daily 단계부터 다시 시도한다.

## Milestone

마일스톤 연결은 선택 사항이다. 신규 Task는 과거 Task나 템플릿의 관계값을 복사하지 않고 기본적으로 비워 둔다. Task 목표가 특정 마일스톤의 산출물이나 완료 기준에 직접 기여할 때만 TaskBoard의 `마일스톤` 관계가 가리키는 Milestones 데이터베이스에서 후보를 조회한다. 후보 페이지에서 다음 세 가지를 모두 확인한 경우에만 연결한다.

- 업무 내용과 해당 마일스톤 범위가 구체적으로 일치한다. 프로젝트명이나 비슷한 제목만으로 판단하지 않는다.
- 마일스톤의 담당자·참여자에 Notion에서 확인한 **내 사용자 ID**가 포함되어 있다.
- 마일스톤의 현재 상태가 **미완료**다. 실제 상태 옵션과 완료 그룹을 기준으로 Done·완료된 후보는 제외한다.

적격 후보를 특정할 수 없으면 빈 관계가 올바른 결과다. 새 Task를 생성한 직후 다시 읽어 자동으로 붙은 관계도 같은 기준으로 확인하고 의도한 값만 남긴다. 기존 Task의 잘못된 연결을 정정해 달라는 요청에서는 해당 Task의 관계만 최소 수정하고 다시 읽어 확인한다. Milestone 페이지 자체의 상태와 다른 Task의 관계는 보존한다.

## Slack과 PR

- 업무가 시작된 Slack 원문이나 사용자가 지정한 스레드 URL을 Task에 남긴다. 관련 URL이 뒤늦게 주어지면 같은 Task에 추가한다.
- 사용자가 이 업무의 PR 생성을 요청하면 기존 PR 템플릿을 유지하고 본문의 `관련 링크`에 Notion Task와 확인된 Slack URL을 넣는다. 사내 링크를 공개 저장소 등 더 넓은 독자에게 노출하는 경우에는 공유 범위를 먼저 확인한다.
- PR 생성 결과 또는 이미 지정된 PR의 실제 URL을 Task에 추가한다. 링크용 속성이 있으면 사용하고, 여러 PR을 담을 수 없는 속성이면 본문에 목록으로 남긴다. 기존 URL·본문은 보존하고 같은 링크는 한 번만 쓴다. 재시도 때는 이미 열린 PR과 작성된 링크를 확인한다.

## 완료와 결론

1. 시작할 때 정한 완료 기준과 실제 결과를 대조한다. PR 제출 자체가 완료 기준이면 제출로 마감할 수 있다. 리뷰·병합·배포가 기준에 포함되면 해당 결과까지 확인한다. 막혔으면 진행 상태와 미체크 TODO를 유지하고 Task에 막힌 지점과 남은 일을 적는다.
2. 먼저 Task 본문과 상태를 읽는다. **완료 요약**에 팀원이 이해할 수 있도록 한국어로 결론을 쓴다. 무엇이 어떻게 달라졌는지, 무엇으로 확인했는지를 구체적으로 적고, 인계할 일이 있으면 덧붙인다. 조사 업무라면 확인한 원인과 결정한 조치를 남긴다. 예를 들어 “정산 내역을 다시 내려받을 때도 환불 건이 포함됩니다. 누락됐던 2월 사례로 재조회해 화면과 CSV 금액이 일치하는 것을 확인했습니다.” 링크는 관련 링크 영역에 유지한다. 재시도 때 기존 요약이 검증된 결과와 일치하면 그대로 두고 누락되었거나 달라진 내용만 반영한다.
3. 사용자가 별도로 “Notion도 마감해줘”라고 할 때까지 미루지 않는다. 완료 기준을 충족한 응답에서 **최종 답변 전에** 요약을 확인한 뒤 상태가 아직 완료되지 않았을 때만 속성 업데이트로 `Status = DONE`을 적용한다. 업데이트 후 Task를 다시 fetch해 완료 요약과 실제 `DONE` 값을 확인한다. 이미 `DONE`인 Task도 Daily 확인 단계로 이어간다.
4. 시작 때 보관한 Daily 링크와 아직 동기화 보류 중인 업무일을 함께 확인한다. 예전 날짜가 이미 체크됐어도 보류 중인 날짜까지 확인한다. 각 대상 Daily를 열어 **🎯 오늘 할 일** 안에서 **Task 페이지 ID**가 일치하는 멘션 체크박스를 찾는다. 미체크면 멘션과 제목을 보존하며 그 항목만 `[x]`(또는 `checked="true"`)로 바꾼다. 이미 체크된 항목은 재사용한다. Daily 역링크가 빠졌다면 시작 기록의 날짜·작성자·Daily URL로 올바른 페이지를 확인한다. 그 날짜의 항목 자체가 누락됐다면 [Daily 반영 절차](#오늘-daily에-즉시-반영)에 따라 해당 페이지에 체크된 멘션 하나를 복구한다. 날짜나 페이지를 특정할 수 없으면 보류 사유를 알린다. 마감하는 날짜로 원래 Daily를 대체하지 않는다.
5. 수정한 각 Daily를 다시 fetch해 같은 Task ID의 체크박스가 **체크된 상태**인지 확인한다. 관계/롤업 형식의 Daily는 해당 Task 행이 실제로 완료로 표시되는지 확인한다. 일부 쓰기나 재조회에 실패하면 최신 값을 읽고 빠진 쪽만 복구한다. 계속 실패하면 예를 들어 “Task DONE 확인 · 11/25 Daily 체크 보류(권한 없음)”처럼 확인된 결과와 남은 항목을 실제 링크와 함께 보고하고, 로컬 Task 기록을 유지한다.
6. **Task DONE과 연결된 Daily 체크가 모두 확인된 뒤** 로컬에 기억된 URL도 이 Task와 일치할 때만 그 기록을 `python3 <스크립트> clear <Task-URL>`로 해제한다. 최종 답변에 업무 결론, 확인된 Task와 Daily 링크를 함께 남긴다.

Notion이나 PR 쓰기가 도중에 실패하면 성공한 쪽의 URL과 남은 작업을 알려준다. 재개 시 해당 항목을 읽고 빠진 변경만 적용한다. 생성 응답이 불확실하면 원격 결과를 먼저 대조하고, 식별할 수 없으면 새 항목을 만들지 않는다. Notion MCP가 꺼져 있으면 추적이 보류된 사실을 알리고 독립적으로 수행 가능한 본업은 계속한다.
