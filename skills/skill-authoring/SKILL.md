# Skill Authoring

이 저장소는 두 가지를 배포한다.

- **큐레이션** — 남이 만든 플러그인을 내 마켓플레이스 항목으로 노출한다. 내용을 복사하지 않고 원본 저장소를 가리킨다.
- **자작** — `skills/` 아래 내가 쓴 스킬. `source: "./"` 번들로 묶어 노출한다.

둘 다 `.claude-plugin/marketplace.json` 하나에 들어간다.

## 스킬 추가

1. `skills/<name>/SKILL.md`를 만든다. frontmatter의 `name`은 **폴더명과 같아야 한다**.
2. 참조 문서·스크립트·런타임 사이드카를 **같은 폴더 안에** 넣는다. 공용 디렉토리를 새로 만들지 않는다 — 스킬 폴더를 통째로 옮겨도 동작해야 한다.
3. `marketplace.json`의 번들 `skills` 배열에 경로를 추가한다. **이 단계를 빠뜨리면 스킬이 조용히 배포에서 빠진다.**
4. `scripts/validate.sh`를 돌린다.

```
skills/<name>/
├─ SKILL.md              # 필수
├─ reference/            # 참조 문서 (선택)
├─ scripts/              # 스킬이 실행하는 스크립트 (선택)
└─ agents/openai.yaml    # Codex 전용 프로파일 (선택). 다른 런타임은 무시한다
```

## description 작성

스킬의 실효 품질은 본문보다 `description`이 좌우한다 — 그게 트리거이기 때문이다.

- **언제 쓰는지**를 사용자의 표현으로 쓴다. 무엇을 하는지만 쓰면 안 걸린다.
- 사용자가 실제로 칠 법한 표현을 넣는다.
- 겹치는 스킬이 있으면 **배제 조건**까지 적는다 ("~할 때는 쓰지 않는다").

## 번들 경계

- **목적으로 나눈다.** 함께 켜고 끄고 싶은 단위가 번들이다.
- **런타임으로 나누지 않는다.** 그게 단일 정본 원칙을 깨는 가장 흔한 방식이다.
- **always-on 비용으로 나눈다.** 항상 켤 것과 가끔 쓸 것은 다른 번들에 둔다.

설치된 스킬은 전부 always-on 비용을 낸다. 번들을 늘리기 전에 확인한다.

```sh
claude plugin details <bundle>   # 컴포넌트 인벤토리 + 예상 토큰
```

스킬을 늘리는 것보다 **안 쓰는 스킬을 지우는 것**이 대개 더 큰 개선이다.

## 큐레이션 항목 추가

원본 저장소 루트에 `.claude-plugin/plugin.json`이 있으면 그대로 가리킨다.

```json
{
  "name": "<원본 plugin.json의 name과 동일하게>",
  "description": "내가 왜 이걸 쓰는지",
  "category": "workflow",
  "source": {
    "source": "url",
    "url": "https://github.com/<owner>/<repo>.git",
    "ref": "main"
  }
}
```

플러그인이 저장소 **서브디렉토리**에 있으면 `git-subdir`를 쓴다.

```json
"source": {
  "source": "git-subdir",
  "url": "https://github.com/<owner>/<repo>.git",
  "path": "product-management",
  "ref": "main"
}
```

### 반드시 지킬 것

- **HTTPS만 쓴다.** `{"source": "github", "repo": "..."}` 형식은 SSH(`git@github.com:`)로 클론을 시도해 키가 없는 머신에서 실패한다. 새 머신에서만 터지므로 로컬에서는 보이지 않는다.
- **`url`에 `path`를 붙이지 않는다.** `url` 소스는 `path`를 **조용히 무시하고** 저장소 루트를 통째로 받는다. 플러그인이 없는데도 설치 성공을 보고하고 스킬 0개가 들어온다. 서브디렉토리는 반드시 `git-subdir`다.
- **`ref`를 명시한다.** 기본값에 의존하지 않는다.
- **`name`은 원본 `plugin.json`의 `name`과 맞춘다.** 다르게 쓰면 설치 후 조회가 엇갈린다.
- 설치 후 **`claude plugin details <name>`으로 스킬 수를 확인한다.** 0개면 소스 형식이 틀린 것이다.

### 버전 정책

이 저장소는 **ref 추종**이다. `sha`를 고정하지 않고 업스트림 기본 브랜치를 따라간다. 항상 최신을 받는 대신, 업스트림이 깨지면 그대로 전파된다.

특정 항목만 고정하고 싶으면 그 항목에 `"sha": "<커밋>"`을 추가한다. 그 항목은 sha를 직접 올릴 때까지 멈춘다.

### 큐레이션한 뒤 할 일

원본 마켓플레이스를 따로 등록해 두고 있었다면 **제거한다.** 그대로 두면 같은 플러그인이 두 마켓플레이스에 존재해 `<name>@<marketplace>`가 갈린다. 등록을 하나로 줄이는 것이 큐레이션의 목적이다.

## 검증

```sh
scripts/validate.sh
```

릴리스 전에는 실설치 스모크까지 한다 — 마켓플레이스 등록 → 설치 → 컴포넌트 인벤토리 확인 → **정리**. 정리를 빠뜨리면 다음 실행이 오염된다.

## 비밀

이 저장소는 공개다. 설정 템플릿에는 값이 아니라 자리표시자(`${ENV_VAR}`)만 넣는다. 토큰·API 키·인증 파일은 어떤 형태로도 커밋하지 않는다.

실수로 커밋했다면 히스토리 재작성보다 **즉시 키 회전**이 먼저다. 공개 저장소에 올라간 값은 이미 유출된 것으로 간주한다.
