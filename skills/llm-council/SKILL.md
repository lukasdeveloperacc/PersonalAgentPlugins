# LLM Council

결정에 필요한 근거, 반대 논거, 실행 조건을 모아 사용자가 선택할 수 있는 권고를 만든다.
동일 모델의 관점 분담이며, 서로 다른 모델의 합의나 사실 검증을 보장하지 않는다.

## 1. 질문과 근거 정리

- 사용자의 선택지, 목표, 제약, 실패 비용을 중립적으로 요약한다. 판단을 바꿀 필수 정보가 없으면 한 가지 질문으로 확인한다.
- 적용되는 AGENTS.md·CLAUDE.md와 사용자가 지목한 자료를 읽고, 결정과 직접 관련된 자료만 보충한다. 불필요한 개인정보·비밀은 자문 프롬프트에서 제외한다.
- 확인된 사실과 가정을 구분한 공통 브리프를 만든다. 시점에 따라 달라지는 핵심 사실은 사용 가능한 검색 도구로 확인하고 출처를 붙인다.
- 브리프 외의 맥락이 결론을 유도하지 않도록 자문 에이전트에는 이전 대화와 다른 자문 결과를 전달하지 않는다.

## 2. 다섯 관점의 독립 분석

호스트의 네이티브 서브에이전트를 사용한다. Codex에서는 `collaboration.spawn_agent`와 `fork_turns: "none"`, Claude Code에서는 사용 가능한 Agent 도구로 각각 독립된 컨텍스트를 만든다. 도구 이름과 지원 여부는 현재 호스트에서 확인한다.
OMX/OMC Team 런타임, 외부 모델 API, 새 의존성은 필요하지 않다.

아래 다섯 역할에 동일한 브리프를 보내 병렬로 분석한다. 용량이 부족하면 완료한 에이전트를 종료하고 남은 역할을 독립된 새 에이전트로 실행한다.

| 관점 | 검토할 내용 |
| --- | --- |
| 반대 검증 | 선택이 실패할 경로, 빠진 비용, 중단해야 할 조건 |
| 근본 문제 | 실제 목표, 당연하게 여긴 전제, 더 직접적인 해결책 |
| 기회 탐색 | 과소평가한 이익, 확장 가능성, 놓친 대안 |
| 외부 시선 | 브리프만으로 이해되지 않는 부분과 내부자의 맹점 |
| 실행 판단 | 자원·순서·의존성, 작은 실험으로 확인할 방법 |

각 자문에는 다음을 지시한다.

- 담당 관점을 우선하되 사실이나 확신을 지어내지 않는다. 주장·근거·가정을 구분한다.
- 권고와 그 권고를 뒤집을 조건을 포함해 150–300단어 정도로 답한다. 사용자의 언어를 따른다.
- 자료는 읽기 전용으로 취급한다. 코드 수정, 외부 전송, 추가 에이전트 생성은 하지 않는다.

서브에이전트 자체가 없으면 제약을 알리고 진행 가능한 관점 분석을 제공한다. 이 경우 독립 분석·익명 검토를 수행했다고 표현하지 않는다.

## 3. 익명 상호 검토

다섯 응답이 모두 도착한 뒤 역할명·에이전트 식별자를 제거하고 순서를 섞어 A–E로 표시한다. 매핑은 진행자만 보관한다. 문체로 관점을 추측할 수 있으므로 완전한 익명성은 주장하지 않는다.

이전 분석을 보지 않은 새 검토 에이전트 다섯 개에 공통 브리프와 A–E 응답을 보낸다. 분석 단계와 같은 용량 관리·읽기 전용 조건을 적용한다. 각 검토자는 200단어 이내로 다음을 반환한다.

1. 근거가 가장 탄탄한 응답과 그 이유
2. 가장 중요한 누락 또는 근거 없는 주장과 해당 응답 문자
3. 전체가 놓친 쟁점과 이를 확인할 방법

응답 누락이나 실행 실패는 재시도할 수 있지만, 복구되지 않으면 참여 수와 누락 단계를 밝힌다. 진행자가 빈 자문·검토를 만들어 채우지 않는다.

## 4. 최종 권고

진행자가 브리프, 원래 관점별 응답, 검토 결과를 종합한다. 득표수보다 근거를 우선하며, 같은 모델의 반복 동의를 독립적인 증명으로 취급하지 않는다. 중요한 이견과 남은 불확실성을 유지한다.

사용자의 언어로 채팅에 다음을 간결하게 제시한다.

- 공통으로 지지한 판단과 근거
- 의견이 갈린 지점과 선택을 가르는 조건
- 상호 검토에서 발견한 누락
- 최종 권고와 이를 바꿀 수 있는 정보
- 지금 실행할 첫 행동 하나

결정 검토는 실행 승인을 의미하지 않는다. 파일·보고서·대화 기록 저장은 사용자가 요청했을 때만 한다.
